ExecuteCachedAsync

Deduplicate both the async fetch AND the state updates. When multiple components load the same data, only 2 state updates occur instead of N×2.

New in v2.0.5

Combines the best of ExecuteAsync and LazyLoad - automatic state management with full deduplication across components.

The Problem

When using ExecuteAsync with LazyLoad, you get fetch deduplication but NOT state update deduplication:

The Problem: N×2 State Updates
// Component 1 calls LoadProduct:
await ExecuteAsync(
    () => LazyLoad("product-123", () => api.GetProduct(123)),
    loading: s => s with { Product = s.Product.ToLoading() },  // Update #1
    success: (s, p) => s with { Product = AsyncData.Success(p) } // Update #2
);

// Component 2 calls LoadProduct:
// LazyLoad deduplicates the fetch (good!)
// BUT ExecuteAsync still runs its callbacks...
await ExecuteAsync(
    () => LazyLoad("product-123", () => api.GetProduct(123)),
    loading: s => s with { Product = s.Product.ToLoading() },  // Update #3
    success: (s, p) => s with { Product = AsyncData.Success(p) } // Update #4
);

// With 5 components: 10 state updates instead of 2!

The Solution: ExecuteCachedAsync

ExecuteCachedAsync deduplicates everything - the fetch AND the state updates:

The Solution: Only 2 State Updates
// Component 1 calls LoadProduct:
var product = await ExecuteCachedAsync(
    "product-123",
    async () => await api.GetProduct(123),
    loading: s => s with { Product = s.Product.ToLoading() },  // Update #1
    success: (s, p) => s with { Product = AsyncData.Success(p) }, // Update #2
    cacheFor: TimeSpan.FromMinutes(5)
);

// Components 2-5 call LoadProduct:
// They all wait for the same result
// NO additional state updates!

// Total: 2 state updates, not 10
How It Works
  • First caller triggers loading state and starts the fetch
  • Concurrent callers wait for the result without triggering state updates
  • Single success/error state update when the fetch completes
  • All callers receive the same result

API Reference

Method Signature
Task<TResult> ExecuteCachedAsync<TResult>(
    string cacheKey,
    Func<Task<TResult>> asyncAction,
    Func<TState, TState> loading,
    Func<TState, TResult, TState> success,
    Func<TState, Exception, TState>? error = null,
    TimeSpan? cacheFor = null,
    CancellationToken cancellationToken = default,
    [CallerMemberName] string? action = null
);
Parameter Type Description
cacheKey string Unique key for deduplication. Concurrent calls with the same key share one execution.
asyncAction Func<Task<TResult>> The async operation to execute (e.g., API call).
loading Func<TState, TState> Pure function to transform state when loading starts.
success Func<TState, TResult, TState> Pure function to transform state with the result on success.
error Func<TState, Exception, TState>? Optional. Pure function to transform state on error.
cacheFor TimeSpan? Optional. Duration to cache the result. If null, only deduplicates concurrent requests.
cancellationToken CancellationToken Optional. Token to cancel the operation. Throws OperationCanceledException when cancelled.

When to Use Which Helper

Scenario Best Helper Why
Multiple components load same data ExecuteCachedAsync Deduplicates both fetch and state updates
Single component, unique data ExecuteAsync No deduplication needed
Need data without state management LazyLoad Just returns cached data
Need custom state update logic LazyLoad + manual update Full control over state updates

Real-World Example

Product detail page with multiple components that need product data:

ProductState.cs
public record ProductState(
    AsyncData<Product> Product,
    AsyncData<ImmutableList<Review>> Reviews
)
{
    public static ProductState Initial => new(
        AsyncData<Product>.NotAsked(),
        AsyncData<ImmutableList<Review>>.NotAsked()
    );
}
ProductHeader.razor
@inherits StoreComponentWithUtilities<ProductState>

@if (State.Product.IsLoading) { <Skeleton /> }
@if (State.Product.HasData)
{
    <h1>@State.Product.Data.Name</h1>
    <p>@State.Product.Data.Description</p>
}

@code {
    [Parameter] public int ProductId { get; set; }

    protected override async Task OnParametersSetAsync()
    {
        await ExecuteCachedAsync(
            $"product-{ProductId}",
            async () => await ProductApi.GetAsync(ProductId),
            loading: s => s with { Product = s.Product.ToLoading() },
            success: (s, p) => s with { Product = AsyncData.Success(p) },
            cacheFor: TimeSpan.FromMinutes(5)
        );
    }
}
ProductPrice.razor (same cache key!)
@inherits StoreComponentWithUtilities<ProductState>

@if (State.Product.HasData)
{
    <div class="price">$@State.Product.Data.Price</div>
}

@code {
    [Parameter] public int ProductId { get; set; }

    protected override async Task OnParametersSetAsync()
    {
        // Same cache key = shares result with ProductHeader
        // NO additional state updates!
        await ExecuteCachedAsync(
            $"product-{ProductId}",
            async () => await ProductApi.GetAsync(ProductId),
            loading: s => s with { Product = s.Product.ToLoading() },
            success: (s, p) => s with { Product = AsyncData.Success(p) },
            cacheFor: TimeSpan.FromMinutes(5)
        );
    }
}

Cancellation Support

Pass a CancellationToken to cancel long-running operations:

Cancellation Example
@implements IDisposable

@code {
    private CancellationTokenSource _cts = new();

    protected override async Task OnParametersSetAsync()
    {
        // Cancel previous operation if parameters change
        _cts.Cancel();
        _cts.Dispose();
        _cts = new CancellationTokenSource();

        try
        {
            await ExecuteCachedAsync(
                $"product-{ProductId}",
                async () => await ProductApi.GetAsync(ProductId),
                loading: s => s with { Product = s.Product.ToLoading() },
                success: (s, p) => s with { Product = AsyncData.Success(p) },
                cancellationToken: _cts.Token
            );
        }
        catch (OperationCanceledException)
        {
            // Cancelled - new operation is starting
        }
    }

    public void Dispose() => _cts.Dispose();
}

Key Behaviors

🔗

Full Deduplication

Both the async fetch and state updates are deduplicated across all callers with the same cache key.

⏱️

Optional Caching

Use cacheFor to cache results. Without it, only concurrent requests are deduplicated.

🔄

Error Recovery

Errors are NOT cached, allowing retry on the next call.

📊

Returns Result

Unlike ExecuteAsync, this method returns the result for immediate use.

🛑

Cancellation Support

Pass a CancellationToken to cancel in-flight operations gracefully.

🗑️

Disposable

AsyncActionExecutor implements IDisposable for proper resource cleanup.
